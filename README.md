# NBA home-win probabilities for April 2026

Predicts the probability that the home team wins each of the 96 April 2026 games, using only Oct–Mar data (no external data). Judged on calibration and pricing, not betting ROI.

**Model:** one team-strength rating from point margins (ridge, λ=80, refit each game day), mapped to a probability by a logistic fitted on training games only. Chosen before March was scored.

**Result:** clean test months (March + April, 335 games): +0.162 log loss over always-home, +0.011 over log5 [−0.002, +0.024], i.e. better but not statistically proven. Too cautious late in the season (calibration slope about 1.5). Full write-up: `REPORT.pdf` (recommendation and evidence first, appendix after).

## Run it

The exercise data is private and not included. Put the file at `data/nba-win-probability-data.csv`, then:

```
pip install -r requirements.txt
bash run_all.sh        # about 1 minute; rebuilds every table, figure and file in outputs/
```

## Where things are

**Start here:** `REPORT.pdf` (the write-up) and `outputs/april_predictions.csv` (the 96 April forecasts, one probability per game).

**`src/`: code, in the order `run_all.sh` runs it**

| File | What it does |
|---|---|
| `data.py` | Loads the data and runs integrity checks. March and April are locked until the final scripts run |
| `ridge.py`, `elo.py`, `baselines.py`, `features.py`, `features_extra.py`, `metrics.py` | The models, features and scoring functions |
| `tune_baselines.py`, `tune_elo.py`, `tune_ridge.py`, `tune_features.py`, `check_extra_features.py` | Choose settings and test features, on Oct–Feb only |
| `frozen_config.py` | The chosen settings, frozen before March was scored |
| `final_eval.py` | Scores March once (`march`); `dry` re-checks the Oct–Feb numbers |
| `run_april.py` | Scores April blind: version A (headline) and version B |
| `test_blind.py` | No-look-ahead test: perturbs later outcomes, prints True/True if inputs are unchanged |
| `metrics_deep.py`, `metrics_pooled.py` | Scoring rules, calibration and paired comparisons, Dec–Apr |
| `make_april_files.py`, `make_workbook.py` | Build the April prediction files and the workbook |
| `make_figure_*.py` | The four report figures |

**`outputs/`: everything is regenerated by `run_all.sh`.** Files that would reproduce the private exercise data (outcomes and margins by game) are not committed; they appear when you run the pipeline.

| File | What it is |

## Validation in one paragraph

Dec, Jan and Feb are each scored after fitting on all earlier games; March is scored once; April is scored once with every outcome-based input frozen at 31 March (version A, the headline). Version B lets inputs roll forward through April and differs by at most 0.004 in log loss. No random splits. `test_blind.py` shuffles outcomes after a freeze date (March as a stand-in for April) and checks that version A inputs do not change.

## Limits of the data

No injuries, lineups, resting decisions, travel, pace or possessions, late-season incentives, or market lines. These matter in basketball; they are reasons the model is a baseline, not a finished pricing model. Details in the report.
